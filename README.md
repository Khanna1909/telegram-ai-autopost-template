# Telegram AI Autopost Template

Стартовый конструктор для автоматической подготовки изображения через KIE AI и
публикации комплекта «изображение + текст» в Telegram-канал.

Создан Ханной Имани как учебная основа. Это самостоятельный проект с
нейтральными примерами. Он не содержит чужих секретов, производственного
состояния, личных настроек или закрытой библиотеки промптов.

Это не готовая контент-фабрика и не копия закрытой производственной системы.
Шаблон не придумывает новые темы сам. Пользователь добавляет собственные идеи,
промпты и оформление в понятные YAML-файлы, а код отвечает за генерацию,
публикацию, защиту от дублей и восстановление после сбоя.

## Сначала самое важное

После копирования репозитория **ничего не публикуется автоматически**:

- встроенного cron нет;
- `DRY_RUN=true`;
- `TELEGRAM_ENABLED=false`;
- ручной workflow по умолчанию запускает только `safe-check`;
- для платной генерации нужны сразу три разрешения;
- тесты запускаются с пустыми API-ключами.

Даже если вы добавили Secrets, случайное нажатие обычной кнопки не должно
потратить кредиты KIE или отправить пост.

## Что умеет шаблон

- выбирает один из подготовленных примеров для утреннего, дневного или
  вечернего слота;
- создаёт детерминированный `release_id` вида `2026-07-25-morning`;
- формирует visual prompt с выбранным визуальным режимом;
- создаёт асинхронную задачу KIE;
- повторно использует уже созданный `task_id` и результат;
- проверяет, что файл открывается и имеет достаточный размер;
- отправляет изображение и текст отдельными Telegram-сообщениями;
- продолжает незавершённый шаг после сбоя;
- не отправляет повторно уже опубликованный слот;
- хранит техническое состояние в отдельной ветке `state`;
- ограничивает число новых генераций в сутки.
- бесплатно проверяет ключ KIE, Telegram-бота и доступ к каналу до генерации.

Девять демонстрационных материалов рассчитаны только на три дня при трёх
публикациях в сутки. После этого выбор начнёт повторяться. До включения
расписания замените примеры своими или добавьте новые.

## Три визуальных режима

| Режим | Что разрешено на изображении |
|---|---|
| `clean_visual` | Только художественное изображение и заданная авторская подпись |
| `signature_visual` | Только художественное изображение и заданная авторская подпись |
| `educational_card` | Только заранее подготовленный текст карточки и авторская подпись |

Подпись и текст карточки создаёт генеративная модель. Pillow, SVG, FFmpeg и
ImageMagick не накладывают их программно.

В `educational_card` текст берётся из поля `card_text` и передаётся модели
дословно. Модели запрещается самостоятельно добавлять факты, логотипы и
водяные знаки. Но текст внутри AI-изображений всё равно нужно проверять глазами:
генеративные модели иногда искажают буквы.

OCR не управляет публикацией. В этой версии OCR вообще не используется:
случайные буквы на книгах или предметах не должны запускать повторную платную
генерацию. Публикацию блокирует только технически неисправный файл.

## 1. Сделайте свою копию

Нажмите **Use this template → Create a new repository**.

Вы получите независимый репозиторий. Изменения в нём не затрагивают исходный
шаблон и другие копии.

## 2. Создайте Telegram-бота

1. Откройте в Telegram официального `@BotFather`.
2. Выполните `/newbot`.
3. Сохраните выданный токен.
4. Добавьте бота администратором своего канала.
5. Разрешите ему публиковать сообщения.
6. Подготовьте ID канала или публичное имя вида `@my_channel`.

Не вставляйте токен в `user_config.yaml`, README, Issue или исходный код.

## 3. Получите ключ KIE

Создайте собственный API key в кабинете KIE. Проект использует официальный
Bearer API и модель `gpt-image-2-text-to-image`.

KIE выполняет генерацию асинхронно: сначала возвращается `taskId`, затем
workflow опрашивает состояние и скачивает готовый результат.

Перед включением автоматики проверьте актуальную цену выбранной модели в
кабинете KIE. Шаблон ограничивает число задач, но не знает ваш тариф и баланс.

## 4. Добавьте GitHub Secrets

Откройте:

`Settings → Secrets and variables → Actions → Secrets → New repository secret`

| Secret | Значение |
|---|---|
| `KIE_API_KEY` | Ваш ключ KIE |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `TELEGRAM_CHANNEL_ID` | `@username` канала или его числовой ID |

Secrets нельзя добавлять в fork через код. Каждый пользователь добавляет только
свои значения в настройках своего репозитория.

## 5. Настройте бренд и контент

Отредактируйте [config/user_config.yaml](config/user_config.yaml):

```yaml
brand:
  signature: "ВАШ БРЕНД / ВАШЕ ИМЯ"
  image_intro: "Промпт ниже 👇"
  post_footer: ""
```

В [data/examples.yaml](data/examples.yaml) находятся девять нейтральных
примеров. Для каждого материала задайте:

```yaml
- id: unique-id
  mode: educational_card
  title: "Заголовок сообщения"
  post_text: "Короткое пояснение"
  card_text: |
    ТОЧНЫЙ ТЕКСТ КАРТОЧКИ
    1. Первый пункт
    2. Второй пункт
  visual_prompt: "Описание визуала на английском языке."
```

Для `clean_visual` и `signature_visual` поле `card_text` не нужно.

Не храните в публичном репозитории персональные данные, закрытые промпты,
клиентские документы и конфиденциальную информацию.

## 6. Выполните безопасную проверку

Откройте `Actions → Telegram AI Autopost → Run workflow`.

Выберите:

- `operation`: `safe-check`;
- `slot`: любой;
- `confirm_live`: выключено.

Workflow создаст artifact `telegram-ai-autopost-preview-...` с JSON-файлом:

- выбранный пример;
- визуальный режим;
- полный visual prompt;
- подготовленный текст Telegram.

На этом шаге KIE и Telegram не вызываются.

## 7. Проверьте тесты

Workflow `Tests` проверяет:

- безопасные значения по умолчанию;
- правила трёх визуальных режимов;
- детерминированный `release_id`;
- техническую проверку изображения;
- ограничение длины Telegram-сообщения;
- идемпотентность;
- восстановление по существующему `task_id`;
- запрет повторной отправки изображения;
- дневной лимит генераций;
- отсутствие внешних вызовов в dry-run.

Локальный запуск:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[test]"
pytest
python -m telegram_ai_autopost --operation safe-check
```

## 8. Проверьте подключения без генерации

После добавления Secrets откройте `Telegram AI Autopost → Run workflow`:

- `operation`: `doctor`;
- `confirm_live`: выключено.

`doctor` проверяет:

- принимает ли KIE ваш API key и показывает ли остаток кредитов;
- отвечает ли Telegram-бот;
- видит ли бот указанный канал;
- заменена ли шаблонная подпись;
- корректны ли примеры и уникальны ли их ID;
- через сколько дней примеры начнут повторяться.

Этот режим не создаёт задачу генерации и не публикует пост. Успешный результат
имеет статус `ready` и поле `paid_generation_created: false`.

Важно: `getChat` подтверждает доступ к каналу, но не доказывает право бота
публиковать. Перед live-тестом убедитесь в Telegram, что бот назначен
администратором с правом публикации сообщений.

## 9. Включите live-режим

Откройте:

`Settings → Secrets and variables → Actions → Variables`

Создайте две переменные:

| Variable | Значение |
|---|---|
| `DRY_RUN` | `false` |
| `TELEGRAM_ENABLED` | `true` |

Для реального запуска дополнительно требуется `confirm_live=true`.

Только сочетание этих трёх условий включает KIE и Telegram:

```text
DRY_RUN=false
TELEGRAM_ENABLED=true
confirm_live=true
```

Если хотя бы одно условие не выполнено, workflow создаёт только preview.

## 10. Сделайте один ручной live-тест

В `Telegram AI Autopost → Run workflow` выберите:

- `operation`: `generate`;
- `slot`: `morning`;
- `confirm_live`: включено.

Это уже платный запуск KIE и реальная публикация. Проверяйте его только после
safe-check и успешных тестов.

Первый live-запуск автоматически создаст отдельную ветку `state`. В ней нет
медиа и ключей. Там хранится только техническое состояние публикаций.

## 11. Подключите внешний планировщик

GitHub Actions остаётся исполнителем, но в шаблоне нет встроенного cron. Внешний
планировщик вызывает `workflow_dispatch` по API.

### Создайте отдельный fine-grained token

В GitHub создайте fine-grained personal access token:

- доступ только к вашему новому репозиторию;
- Repository permissions → Actions → Read and write;
- разумный срок действия.

Не отправляйте токен другим людям и не публикуйте его в репозитории.

### Общие параметры задания

Метод:

```text
POST
```

URL:

```text
https://api.github.com/repos/OWNER/REPOSITORY/actions/workflows/autopost.yml/dispatches
```

Заголовки:

```text
Accept: application/vnd.github+json
Authorization: Bearer YOUR_FINE_GRAINED_TOKEN
X-GitHub-Api-Version: 2022-11-28
Content-Type: application/json
```

### Тела четырёх запросов

Утро:

```json
{"ref":"main","inputs":{"operation":"generate","slot":"morning","confirm_live":"true"}}
```

День:

```json
{"ref":"main","inputs":{"operation":"generate","slot":"day","confirm_live":"true"}}
```

Вечер:

```json
{"ref":"main","inputs":{"operation":"generate","slot":"evening","confirm_live":"true"}}
```

Страховочная проверка:

```json
{"ref":"main","inputs":{"operation":"catch-up","slot":"morning","confirm_live":"true"}}
```

Пример расписания для часового пояса `Europe/Moscow`:

| Задание | Время |
|---|---:|
| morning | 10:00 |
| day | 15:00 |
| evening | 20:00 |
| catch-up | 21:00 |

Catch-up проверяет только три слота текущей даты в часовом поясе из
`user_config.yaml`. Уже опубликованные слоты завершаются без KIE и Telegram.

Сначала создайте отдельное выключенное тестовое задание с `safe-check`.
Правильный ответ GitHub API на dispatch: `HTTP 204`.

## Восстановление без повторной генерации

Повторно запустите тот же слот и ту же локальную дату.

Система читает ветку `state` и продолжает с последнего незавершённого шага:

- есть `task_id`, но нет результата: опрашивает существующую задачу;
- есть URL результата: скачивает существующий файл;
- изображение уже отправлено: отправляет только текст;
- публикация завершена: ничего не вызывает.

Новая платная задача создаётся только тогда, когда у релиза нет ни `task_id`, ни
готового результата.

## Ограничения

- Шаблон не создаёт новые идеи, новости или сценарии автоматически. Файл
  `data/examples.yaml` наполняет сам пользователь.
- Девять примеров нужны для демонстрации и повторяются через три дня при трёх
  слотах в сутки.
- Схема `input` у разных моделей KIE может отличаться. Значение по умолчанию
  настроено для `gpt-image-2-text-to-image`.
- Стоимость и доступность моделей меняются. Проверяйте их в KIE.
- Генеративная модель может допустить ошибку в тексте карточки или подписи.
- Внешний планировщик тоже может задержать запрос. Catch-up и состояние защищают
  от пропуска и дублей, но не обещают секундную точность.
- Telegram ограничивает длину сообщения. Длинный текст автоматически делится.
